### 2.1 Canonicalisation posture: Fixed for the receipt, Declared for the registry objects
The bytes that get signed are determined by EIP-712: `uid` equals keccak256(0x1901 || domainSeparator || hashStruct(message)); the assessor recomputed it for every artefact examined with no Insight code read or run (the recomputation is 2.4's evidence; this axis is determined by reading, per §3). The domain is `{name "Insight Execution", version "1", chainId 1}`; v3 carried a fourth domain member (`environment`) that the signer did not encode (H7); v4 returned to three members and signed `environment` as a message field; v5 signs `profileId` as a 45th field inside `encodeType`. The content-addressed registry objects declare their own canonicalisation per object (`digest {algorithm keccak256, canonicalization "RFC 8785 JSON Canonicalization Scheme", scope …}`), the URL identifier being that digest; the scopes differ between objects, and one rule applied to all would give wrong addresses. Recorded as a fact: the receipt is Fixed, the registry is Declared.

### 2.2 Vector agreement: no published vectors
No vector corpus is published for this format, on the implementer's published surfaces or in anything he has sent the assessor, and the methodology's value for that case is the one recorded. The sample endpoints mint a fresh signature on every call (`Cache-Control: private, no-store`), so each pinned sample is one unrepeatable observation, not a vector. Retired layouts "remain signable only through the dedicated sample-role conformance path" (the implementer, 9 September, relayed to the assessor [relayed]); no corpus from that path is published on the implementer's published surfaces or in anything he has sent the assessor. Recorded as a fact, not as failure (methodology §3).

### 2.3 Artefact-specification agreement: not determinable
The axis's procedure imports a distributed artefact and probes its documented entry points. The implementation is a hosted service with no distributed package, and §3 records that case as not determinable rather than as failure. What was measured instead, and is recorded under Observations: the served artefacts' declared types against the published registry types.

### 2.4 Independent recomputability: Independent, for the signature, commitment and content-address layer only
A party that did not author the format (the assessor) recomputed, with this tool's own EIP-712 implementation written from the EIP text and independently with a standard library (eth-account 0.14.0 plus a hand-written encoder for the v3 domain), the `uid` of every artefact examined, the signer of every signed artefact (the packages to the implementer's labelled test key; the served samples to registry keys), `preTradeUidsHash` (H5), `requestHash` (the full digest, not the bare hashStruct), and the content addresses of the 10 September release `0x96d1f624…`, the activation set, the policy and the profile, those four with two independent RFC 8785 serialisers compared byte for byte and a one-byte mutation control run before the result was believed. The same recomputation was run for this revision on the two content-addressed objects it newly relies on, with the same control: the release `0x6e3bd18c…` reproduces from its declared scope, the release object in the response, and promotion v4 `0x6148f427…` reproduces from its declared scope, the promotion object excluding `promotionId`. Those agree with the implementer's values byte for byte, which is what the Independent value records, and the value is scoped to that layer: the profile's nine ordered verdict rules, eight scales, second sentinel, and the pre-images of `measuredFieldsHash` and `reasonCodesHash` have one implementation, the implementer's, and are unreproduced; the one served v5 sample is one data point against nine rules. Marked as a judgment call, twice over: §3 says a private implementation cannot be assessed on §2.2 to §2.4, and the assessor reads §2.4 as a property of the format that a second, public implementation from the text can establish; and the definition's "no coordination on implementation" holds in the narrow sense only, since the assessor and the implementer coordinated on findings (H1 to H9 drove seven repairs, and the implementer's releases cite the assessor's pins as `predecessorSnapshots`), not on either implementation.
